# Lessons Learned

Curated cross-task rules distilled from archived memory.

## Information and Density

### Preserve Information Before Compressing Surfaces
**Rule**: List the personal, site, and navigation facts a page must retain before reducing cards, sections, type sizes, or boundaries.
**Why**: Earlier homepage simplification reduced visual boundaries but also hid personal and site information, while CSS estimates were not enough to prove real viewport density.
**Source**: `llmdoc/memory/archive/2026-07-22/2026-07-22-home-density-and-font-ownership.md`

## References and Domain Models

### Borrow a Layout Layer, Not an Unrequested Content Model
**Rule**: Separate layout, information architecture, visual assets, and interaction when using a reference site, then confirm which layer is actually in scope.
**Why**: A Shiro-inspired asymmetric rhythm was initially coupled to its activity-stream content model, although the desired homepage still needed distinct personal, Blog, Project, and Plog roles.
**Source**: `llmdoc/memory/archive/2026-07-22/2026-07-22-reference-layout-not-content-model.md`

### Preserve Functional Hierarchy During Site-wide Restyling
**Rule**: Inventory visible functions and domain hierarchy before a cross-page redesign, and treat them as acceptance criteria alongside visual consistency.
**Why**: Flattening all pages into the same open-list language weakened Links, removed expected Hero contact paths, and failed to distinguish Plog collections from individual moments or Archives browsing tasks.
**Source**: `llmdoc/memory/archive/2026-07-22/2026-07-22-domain-function-before-visual-unity.md`
